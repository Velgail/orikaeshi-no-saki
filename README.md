# 折り返しの先へ — 状況別指令UI V9

日本語の架空鉄道運転整理ゲームです。実在路線の運転制御には使用できません。既存V9候補を継続し、実ブラウザーで指摘された四つの通常操作を改修しています。プレイ時に外部ネットワークは不要です。

## 起動と操作

公開版：https://velgail.github.io/orikaeshi-no-saki/

ローカルではリポジトリまたは配布ZIPを展開し、既存のNode.jsで `npm start` を実行して `http://127.0.0.1:8765` を開きます。依存パッケージのインストールは不要です。HTMLの直接起動ではなくローカルサーバーを使ってください。

列車や便を選ぶと現在地・担当便・制約と次の判断を表示します。目的を選び、必要な候補を選んで、独立フッターの対象・行先・担当・所要・影響を確認して確定します。通常導線は「高度な手動操作」を使いません。平常便は所定どおり自動発車します。輸送・次の接続・休憩・超勤をどう両立するかはプレイヤーが判断します。

「この編成で代走する」は直近の便を先に示し、後の便は「ほかの便を選ぶ」から選べます。「車庫へ戻す」は担当便のない編成でも直接選び、担当者は「担当候補を比較・変更」で選び直せます。「乗務員の配置・休憩を判断する」は人を選んでからその人の操作を選びます。ほかの人は「ほかの乗務員を選ぶ」から選べます。

担当候補は所在・勤務・休憩・資格・終着後処理の条件から提案します。時間進行で比較欄と合法な入力を保持し、候補を現時点で再検査します。担当入力が条件を失うと理由を示して確定を無効にします。取消・戻る・対象切替・読込は未確定指令を破棄します。確定時にも条件を再検査し、連打や古いイベントの実行を防ぎます。

## 今の運行と将来計画

「運転可能区間で運行する」は現在の全経路を検査します。閉鎖横断などの行先は具体的な区間・方向の理由とともに不可欄へ表示し、APIも同じcheckで拒否します。所定の一時待合せ、片方向再開、既進入列車の安全退出、合法な短縮・部分運転は維持します。

「この便を折返す」には、選択便の現在の到着先・駅または始発駅から閉鎖を横断しない短縮だけを表示します。別の便を選んだとき、選択編成の無関係な現在地で経路を判定しません。閉鎖解消を必要とする短縮は「将来の変更計画を保存する」へ置きます。明示的な実行待ち計画は保存でき、必要な経路・担当条件が成立するまで発車を待ちます。未確定の再開時刻は仮定しません。

予備投入は準備5分→実車庫経路の出庫3分→後処理・編成準備3分→運転区間選択です。各段階をプレイヤーが確定し、担当・番線・喉部を再検査します。1倍は実1秒＝ゲーム1秒、60倍は実1秒＝ゲーム1分です。重大通知・背景移行・ルール閲覧で停止します。保存・読込は端末内1件です。

## 維持した土台

04:00留置から実点呼・出庫・回送・営業を再生して08:00配置を導出します。本線2編成＋補助1＋予備1、車庫4線、番線別進路・鎖錠、旅客目的地の保存、所定・変更・実績の分離、入れ子時刻表・勤務子表、図の両軸フォーカス、主体・件数・期間を持つ実ログを維持します。

15:12固定観察、所定72分周期＋翌接続の復旧判定、限定勤務モデル、法定・所定超勤の同一分重複除外を維持します。資料とモデルの範囲は [references.md](references.md) を参照してください。

## 検証

同一runtimeで127個別テストと13件のHTTP確認が成功しました。通常UIの二つの障害復旧方針と正常無操作を15:12まで実ブラウザーで完走し、結果を照合しています。詳しい確認範囲と残件は [QA.md](QA.md)、攻略は [strategy.md](strategy.md) を参照してください。現行ソース・テストのSHA-256は `source-manifest.json` にあります。

テストは `npm test`、配信確認は `node verification/server_check.mjs`。画面の操作性は実ブラウザーで別途確認しており、DOMスタブ試験だけを実画面検品の代わりにはしていません。
