# 折り返しの先へ

架空の近郊鉄道「青葉線」の指令員として、部分運転、段階再開、編成と乗務員の配置復旧を行う日本語のブラウザーゲームです。線路が開いても成功にはなりません。中央―森ヶ丘の旅客運行を実際に両方向各2本完了し、西側と東側に編成を戻してください。

## 起動（Windows / Mac / Linux）

ブラウザー公開版：[折り返しの先へ](https://velgail.github.io/orikaeshi-no-saki/)

1. ZIPを任意のフォルダーへ解凍するか、このリポジトリをダウンロードします。
2. **既にNode.jsがある環境**では、そのフォルダーでターミナルを開き `node server.mjs` を実行します。`npm install` は不要です。
3. 一般的なデスクトップブラウザーで **http://127.0.0.1:8765** を開きます。終了はターミナルで Ctrl+C。

Node.jsの代わりに既存のPython 3でも `python3 -m http.server 8765 --bind 127.0.0.1`（Windowsでは `py -m http.server 8765 --bind 127.0.0.1`）で起動できます。HTMLの直接ダブルクリックではJavaScriptモジュールを読み込めないため、ローカルサーバーを使ってください。NodeもPythonもない場合は、この納品物だけでは起動できません。本作はソフトウェアをインストールしません。

プレイ時のインターネット接続・外部API・CDN・フォント取得は不要です。参照資料リンクは閲覧時だけ外部サイトへ移動します。ソースとゲームデータはすべてこのフォルダーにあります。

## 最初の一手

「指令卓へ」→「運転開始」。列車を選び、進行方向と行先、操作横の説明を確認して発車してください。現在は全区間正常運転です。現場報告を受信したら、現在の制約に合わせて計画を見直します。

1倍は実1秒＝ゲーム1秒（1分tickは60秒ごと）。早送り60倍は実1秒＝ゲーム1分、240倍は実1秒＝ゲーム4分。次tickまでのゲーム秒を表示します。停止と1分送りで計画できます。選択・入力中も進行し、選択列車・行先・種別・開いた時刻表詳細を維持します。ルール表示中は進行せず余剰時間を捨てます。タブを離れると停止し、復帰後の追いつき進行はしません。重大通知では自動停止し、通知確認後に速度を選び直します。通常操作の結果は現場報告を上書きしません。時刻・進行操作は上部、選択と操作は右側に固定しています。

列車・編成一覧か略図をクリックして対象を選びます。操作の横に所要時間、輸送効果、不可理由を表示します。各駅3分走行＋1分停車、折り返し3分、交代2分、休憩8分。行先を再指定するには駅で抑止してください。自動折り返しは明示的にONにした列車だけ有効で、抑止で解除します。運転開始時は全列車OFFです。自動往復は起点番線と到着番線の進入・逆向き出発進路が成立する場合だけONにできます。桜町・川原・丘の上の1番線は西着／東発、2番線は東着／西発で、逆向き出発信号がありません。片道到着後は同方向へ続行します。学園前・新都心の1・4番線、東川原の1番線は両方向進路があり折返可能です。終端は本線側へ戻る信号・進路があります。途中ONも同じ経路規則で検査します。

乗務時間上限は走行36分。発車判断では停車時間も含めた所要時間で余裕を見ます。中央・新都心・森ヶ丘で休憩できます。交代はこの3駅と学園前・東川原で、駅に休憩済みの待機乗務員が必要です。森ヶ丘のF4は予備編成で、最初に「交代・予備投入」が必要です。

待機乗務員は列車に同乗させて運べます。運用を指定する前に「待機乗務員同乗」を押し、通常の旅客運行か回送で目的地へ届けます。途中駅で降ろす場合は停車中に抑止し「同乗乗務員降車」。担当を交代した古い乗務員はその駅に残るため、拠点まで同乗で連れ帰ると休憩できます。取扱い・乗務員の位置・区間占有を解消する手段であり、瞬間移動はありません。

旅客は次の駅までの移動として簡略化し、各区間最大80人を輸送します。総待ち時間は毎分の全駅待ち人数の累積（人分）。評価は輸送人・区間 − 総待ち人分÷100 ＋ 復旧達成500、下限0。結果には両方向の完了本数、配置、全線再開時点の乗務余裕、操作履歴を表示します。未達のまま10:00になると終了します。

列車別時刻表は、プレイヤーが運用を指定した時刻を予定発車として、各駅の予定着・発を確定します。既定の自動ダイヤはありません。競合待ちでも予定を変更せず、実発車・到着実績・遅れを表示します。駅別詳細を開くと途中駅も確認できます。抑止や乗務余裕不足で未完了の運用を解除すると「運休」として残ります。未発生の事故・復旧予定表は表示しません。

保存形式は版4です。不正な自動往復や、折り返し不可駅で実到着方向と異なる保存は拒否します。旧版の保存は読み込まず、日本語の理由を表示して現在の状態を保持します。

ゲーム内「ルール」で詳細を確認できます。「保存」はブラウザーのローカル領域に全状態を1件保存し、「読込」は停止状態から再開します。ブラウザーやURLが違うと保存は共有されません。保存不可・破損・異なる形式では日本語の理由を示し、現在の状態を保持します。「やり直し」「再プレイ」で最初へ戻れます。

## テスト・確認

既存のNode.jsで `node --test tests/*.test.mjs`（または `npm test`）。依存パッケージは不要です。ローカルサーバーの配信検証は `node verification/server_check.mjs`（8765番をほかで使っていない状態）。

今回版は、エンジン・設備・時間進行・DOM操作の33試験を独立再実行し、すべて成功しました。別途、23番線・46方向の折返条件を設備の期待表と照合しています。2つの戦略の復旧完走はエンジン試験で確認済みです。

さらにデスクトップ約1160×746の実ブラウザーで、1倍の連続運転中の選択・行先変更・説明読取・発車・予備投入、重大通知での自動停止と持続表示、番線ごとの折返可否、保存・読込、配線の可読性を確認しました。今回版の実ブラウザーで全復旧まで通しプレイしたわけではありません。スマートフォンとWindows/Mac各実機も独立検証していません。

検証範囲と残件は [QA.md](QA.md) に記録しています。QAにはシナリオ進行の詳細が含まれます。図は横スクロール式で、選択列車への自動追従はまだありません。

駅間は両方向共用の単線1閉塞です。equipment.js に番線、左右の接続、方向別場内・出発進路、信号、線分ID、ポイントのstem/normal/reverse、必要転換状態、進路鎖錠資源を定義しています。手動・自動・保存検証・図はこのデータを参照します。逆向き出発経路の存在が折返可否の根拠です。番線選択は進入と必要な続行方向を満たし、終着では折返可能な空き番線を優先します。必要番線が満杯なら駅で待ちます。番線変更・入換・代用閉塞・手信号は実装しません。予備編成は森ヶ丘の駅番線に待機します。略図は横スクロールで実寸の文字を読めます。中立の枠記号＋矢印は出発方向、灰色矩形はホーム、終端縦線は車止めです。枠記号は設備の有無と方向だけを示し、実際の停止・進行現示はモデル化しません。選択駅の別表で経路の設定可能・閉塞待ち・進路鎖錠中・経路なしを表示します。設定可能でも経路は未設定で、発車操作で設定・鎖錠します。この設備は架空設定であり実在路線の安全判断・運転制御には使えません。

設備の原理参考：日本信号「信号機の種類」https://www.signal.co.jp/products/railway/faq/faq07/ 、JRTT「信号」https://www.jrtt.go.jp/construction/technology/signal.html 。これらの設備原理を設計参考に使用し、外部画像は転載していません。
